# Decisions

One line each: date, decision, why.

- 2026-10-09 · Stack: Vite + TypeScript (strict) + Preact + @preact/signals, Dexie, vite-plugin-pwa, Vitest, Playwright. · Brief §3; approved with the phase 0 plan.
- 2026-10-09 · Vite 8 and Vitest 5 instead of the planned Vite 6 / Vitest 3. · Vitest 3 pulled in packages with open security advisories (tinypool, @vitest/mocker); the current majors audit clean.
- 2026-10-09 · Fonts self-hosted through @fontsource (Atkinson Hyperlegible Next and Mono), bundled by Vite. · Brief §2.5 and §3: no third-party requests at runtime.
- 2026-10-09 · v1 export obtained by adding an "Export everything (JSON)" button to v1's Log tab; the export lives in `private/`, never in git. · v1 had no export, and this keeps the data out of any chat.
- 2026-10-09 · Service worker generated by vite-plugin-pwa's generateSW, not injectManifest. · Phase 0 only precaches and prompts for updates; custom service-worker code (push) arrives in phase 3, when we switch.
- 2026-10-09 · Importer keeps v1 place ids (`france`, `cairo`) as place ids, named from the id, with a time zone from a small lookup or the device's zone. · `where` values stay valid with no rewrite; names and zones are editable in Settings.
- 2026-10-09 · v1's `spent` is not stored on tasks; it's derived from sessions. A task whose `spent` didn't match its sessions keeps the v1 figure as `spentV1`. · Brief §4; on the real export no task differed.
- 2026-10-09 · Imported fields carry the oldest possible clock. · Re-importing never overwrites anything edited in v2.
- 2026-10-09 · Close the day in phase 0 shows v1's summary (count, suits, tomorrow's first step) without the card show. · The show is rebuilt from scratch in phase 1 (brief §5); porting v1's canvas only to replace it would be waste.
- 2026-10-09 · Backups are plain JSON in phase 0. · Encrypted backups need the key from phase 3's sync setup.
- 2026-10-09 · WebKit e2e tests run in Playwright's official container (`npm run e2e:webkit`). · WebKit's Linux build needs Ubuntu libraries Fedora doesn't ship. Playwright's WebKit can't test service workers offline, so offline is tested in Chromium and by hand on iPhone.
- 2026-10-09 · Credit line for the method's author: not shown. · Waiting for Nelly Darmon's answer on the wording (brief §7).
- 2026-10-09 · The place switcher opens a list of places instead of v1's two-way toggle. · Places are no longer limited to two.
- 2026-10-09 · Firefox is the main desktop browser for tests (`npm run e2e`); WebKit and iPhone emulation run in the container; Chrome only as Android emulation. · Samy uses Firefox. Firefox on Linux can't install web apps, so on the desktop Réussite is a tab that works offline once loaded.
- 2026-10-09 · Persistent storage is requested on a tap (Settings → Data) and after an import, never on load. · Firefox shows a permission prompt for it.
- 2026-10-09 · E2E tests use their own port (4174) and always rebuild. · A preview server left running on 4173 made a test run silently reuse an old build.
- 2026-10-09 · Credit line, given by Samy: "Designed by Samy Bishay and built with Claude Code. Special thanks to Nelly Darmon, psychologist." (and its French version), in the footer and About; kept in the `credit` setting per language. · Brief §7; "designed" is the truthful word for the product and UX work, the code being written with Claude Code.
- 2026-10-09 · French strings are optional while building: `fr.ts` is `Partial<Strings>`, missing keys fall back to English, and are translated in one batch at the end of each phase. · Samy: French isn't a priority mid-phase; one pass per phase is cheaper than two edits per string.
- 2026-10-09 · Schema 2: decisions get the structured shape (problem fields, option and item ids, status, history); v1's free-text problem goes into `problem.what`. The importer builds schema 1 and runs the same migrations. · Brief §4 and §9; one path for imported and stored data.
- 2026-10-09 · A repeating step done late comes back on the first scheduled date after the day it was done, never already overdue. · "A missed occurrence isn't duplicated" (brief §5); otherwise a daily step missed for a week would come back six times.
- 2026-10-09 · "Plan the day" is a real step, done when the plan is accepted, timed from opening the check-in, in ♠ and the inbox. · Brief §5: planning is real work and the day's bar starts with it played.
- 2026-10-09 · Fixed commitments typed at the check-in are steps with `fixed`, `at`, `dur` and that day as due date; they show on Today and the calendar but aren't work steps, aren't carried and aren't in the matrix. · Brief §4 (fixed times) without cluttering the list.
- 2026-10-09 · Planner: carried steps and Quick steps count towards the work-step limit; one slot is kept for Protect even when carried steps fill the day; "An hour or less" fits work steps into 60 minutes; "Afternoon only" allows one step fewer; a light day is under half the median of the last 14 accepted plans (default: limit × 30 min). · METHOD: at most three work steps, exactly one Protect.
- 2026-10-09 · Personal estimates: a step with mixed session sources gets the minute-weighted source weight; the project class needs 3 points like the app class; class shrinkage uses the count n; the size slope is shrunk by n/(n+15); AI estimates get their own offset from 3 weighted points. · Details the brief leaves open; all unit-tested.
- 2026-10-09 · "Before I leave" is stored as the step's due date and rewritten when the stay's dates change. · Everything that reads `due` (urgency, matrix, calendar) keeps working unchanged.
- 2026-10-09 · The current place is computed (the stay today belongs to, else the place chosen by hand); the place page being viewed is device-local and not synced. · Brief §5; viewing another place is a momentary look, not data.
- 2026-10-09 · The decisions list lives in the Log; a decision's page and the wizard open as sheets. · Brief §9 asks for the list and page; a seventh tab would crowd phones.
- 2026-10-09 · Matrix and calendar drag use HTML drag-and-drop (desktop and iPad); on phones, long-press or the ⇄/⋯ button opens the Move menu. · Brief §5.
- 2026-10-09 · Sound defaults to on everywhere until it's tested whether the iPhone silent switch mutes it. · Brief §5 says to test first; needs a real iPhone.
- 2026-10-09 · Close-of-day deal pace: 9 s divided by the number of cards, between 0.3 and 0.8 s per card. · Brief §5: 0.6–0.9 s a card and the whole deal under ten seconds; long days go faster.
- 2026-10-09 · WebKit e2e runs with two workers. · More made WebKit crash inside the container.
- 2026-10-09 · Weights are never taken from an AI: any `w` in a change-set is dropped when it's parsed, and an AI's column items start at weight 3 with `by: 'ai'`. · Brief §9 ("AI never proposes weights"); a pasted reply can't prove the person typed a weight, so none are accepted.
- 2026-10-09 · The AI key lives in this device's `local` table, one per provider; it's never in the synced settings or in backups. · Brief §11; "sync my AI key" needs the encrypted sync of phase 3.
- 2026-10-09 · The Content-Security-Policy is a meta tag added to the built page only, with `connect-src 'self' https:`. · A meta CSP can't follow the base URL chosen in Settings, so any https origin is allowed; the dev server needs inline HMR and a websocket. Revisit with the relay in phase 3 (a header CSP from Pages can list the relay).
- 2026-10-09 · AI calls use `fetch` from the browser, with no SDK. · No third-party runtime code (brief §11); two small adapters cover OpenAI-compatible services and Anthropic (with `anthropic-dangerous-direct-browser-access`).
- 2026-10-09 · Change-set v1: dotted ops (`task.create`…`decision.update`) with `ref` names for things created in the same set; each change is checked on its own, bad ones are counted and left out, and a set with none valid is rejected. · One wrong line from a chatbot shouldn't throw away the rest, and nothing invalid is ever written.
- 2026-10-09 · Prompts to the AI are written in English and end with "Answer in <the person's language>". · They aren't UI text; the method itself is sent in the person's language.
- 2026-10-09 · "Show me what's sent" opens in a layer above any open sheet; the kinds already shown are remembered on the device. The connection test skips it. · A feature's own sheet stays open underneath; the test sends nothing about the person.
- 2026-10-09 · Default models: Claude Haiku 5.5 (quick) and Claude Sonnet 5.5 (thinking), as `claude-haiku-5-5`/`claude-sonnet-5-5` on Anthropic and `anthropic/claude-haiku-5.5`/`anthropic/claude-sonnet-5.5` on OpenRouter. · Cheap and fast for the command box, stronger for plans and decisions; both editable in Settings.
- 2026-10-09 · The command box sends today's open list plus at most 25 open steps, the ones sharing the most words with the request first. · Brief §10: never the whole list.
- 2026-10-09 · An AI plan is checked with `checkPlan` against the rule-based plan as a baseline: a rule the rule-based plan itself can't keep (a rest day, an hour) isn't held against the AI. `checkPlan` also wants the obligation, and counts carried steps by id. · Brief §10 "exactly one Protect, one obligation"; relabelling carried steps mustn't stretch the work-step limit.
- 2026-10-09 · A rejected AI plan throws away its starters and splits too. · Its proposals were made for a plan that broke the rules; the rule-based plan stands alone.
- 2026-10-09 · Inside a flow, AI proposals use the review list inline (`ReviewList inline`) rather than the review sheet. · There's one sheet at a time; opening the review would close the check-in, the decision or the weekly review.
- 2026-10-09 · Ticked updates of the same decision are merged when applied (`mergeDelta`). · Each change was planned against the same snapshot, so a second problem line or column item overwrote the first; per-line ticking needs both to land.
- 2026-10-09 · Break it down with AI: each step waits for the one before, in the AI's order; the first keeps the original step's id. An estimate stays `estBy: 'ai'` only if the person leaves it unchanged. · Same shape as breaking down by hand; an edited number is the person's.
- 2026-10-09 · Decision help's drafted steps go into the Steps screen's draft list, to edit or remove; its SMART goal is ticked and marked proposed. One AI kind, `decision`, covers the four kinds of decision help. · Steps are only created on Finish, as by hand; "Show me what's sent" once for decisions is enough.
- 2026-10-09 · Stuck with AI only fills the smaller-starter field; restarting is what saves it. · The person accepts or edits it before anything is written.
- 2026-10-09 · zod runs jitless (`src/zod-config.ts`, imported first). · Its compiled parsers probe for eval when a schema is built, which the CSP blocks and reports as a violation; the plain parser is fast enough for AI replies.
- 2026-10-19 · Relay tests use `@cloudflare/vitest-plugin`, not `@cloudflare/vitest-pool-workers`. · The pool package is deprecated (renamed); the plugin supports Vitest 5 like the app, and audits clean.
- 2026-10-19 · The relay is its own npm project in `relay/`, importing `src/sync` and `src/data` from the app's tree; the root `npm test` and `typecheck` don't touch it (`npm run relay:test`, `relay:typecheck`). · One copy of the crypto, protocol and merge code (brief §10), and the Worker's types (workers-types, no DOM) stay apart from the app's.
- 2026-10-19 · Recovery key: Crockford base32, 32 key bytes plus a 3-byte CRC-32, 56 characters in 14 groups of 4. · Fits a QR code and a line of paper; the checksum catches any single typo (a 1 in 16 million miss for random errors) and the alphabet has no look-alikes.
- 2026-10-19 · The auth hash is SHA-256 of the secret's base64url text, not its bytes. · One canonical string on both sides; no base64 padding ambiguity.
- 2026-10-19 · Blobs are AES-GCM with the format byte and space id as authenticated data; format 1 plain JSON, 2 gzip. · A blob can't be moved to another space or have its compression flag flipped; gzip when the platform has it, readable either way.
- 2026-10-19 · No outbox: a device pushes every field whose clock carries its own node id and is above a watermark. · The clock is monotonic per device, so this is exactly the unpushed set, with nothing to keep in step with the documents. Imported fields (node `0`) are sent on the first sync only.
- 2026-10-19 · A pull that contains a document from a newer schema applies nothing and doesn't advance the sequence number. · The older app goes read-only (brief §11) without writing newer-shaped data into an older database; after the reload the same data is pulled again.
- 2026-10-19 · Blobs are stored on the relay as base64url text and never decoded there. · The relay costs almost no CPU per request (free plan: 10 ms); the price is a third more storage and transfer.
- 2026-10-19 · Caps: a batch blob 1 MiB, a snapshot 4 MiB; a snapshot is stored in 1 MB parts. · A D1 row holds 2 MB; a gzipped personal list is a few hundred KB, so 4 MiB leaves room for years. A device whose snapshot is too big keeps working with batches.
- 2026-10-19 · Rate limits: 60 writes a minute per space (counted on the space's own row, no extra write) and 120 a minute per IP (one D1 row per IP and minute, counting writes and failed sign-ins only). · The free plan allows 100,000 D1 row writes a day; reads are not counted, and a 256-bit secret can't be guessed anyway.
- 2026-10-19 · Reads on an unknown space answer 404 `unknown_space`; a wrong secret answers 403 and nothing is written. · A joining device can tell "nothing there yet" from "wrong key"; the space id is not secret enough to matter.
- 2026-10-19 · A device pushes a snapshot after 50 batches since the last one. · New devices catch up from one blob plus a few batches; the relay's storage stays small.
