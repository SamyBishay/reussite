# Réussite — notes for coding agents

Réussite is a local-first PWA for planning with a CBT method for adult ADHD. The build brief (what to build, by phase) is the Claude doc "Réussite 2 — build brief" on the owner's account (https://claude.ai/code/artifact/b9d2a428-4a60-475c-8f19-e7b64cea1b19), read with the Claude Docs connector. It is background: `DECISIONS.md` and the owner's message win over it. Ignore `BRIEF.md` in this repo: it is out of date. Read `DECISIONS.md` (choices already made) and `docs/METHOD.en.md` (the method) before changing behaviour.

## Commands

| | |
| --- | --- |
| `npm run dev` | dev server |
| `npm test` | unit tests (Vitest) |
| `npm run typecheck` | TypeScript, strict |
| `npm run e2e` | end-to-end tests, Firefox (the main desktop browser) |
| `E2E_CLOCK="2026-11-02 13:00" npm run e2e` | the same suite as if it were then (`HH:MM` for today): the tests' Node side reads that moment; specs that must not depend on the hour pin the browser's clock themselves (`tests/e2e/clock.ts`, `morningClock`, `morningDate`) |
| `npm run e2e:android` | end-to-end tests, Chrome on Android emulation |
| `npm run e2e:webkit` | end-to-end tests, WebKit and iPhone emulation, in Playwright's container (podman) |
| `npm run manual:shots` | the manual's screenshots (`public/manual/shots`), not part of `e2e`; see `docs/dev/manual.md` |
| `npm run build` | production build into `dist/` |
| `npm run check:import`, `npm run check:app` | run the importer and the app on the real export in `private/`; they print counts only |

## Layout

- `src/domain/` — pure functions with no I/O: dates and the day-start rule, urgency and quadrants, ratio, duration buttons, link resolution, repeats, chains (`chains.ts`: steps that wait for one another as one card, one pure index shared with the relay), event steps (`events.ts`: something waited for, its nudge and the Waiting for list), personal estimates, the planner, decision scores, stays, matrix moves, calendar grids, and Home's: the line parser (`parse.ts`, grammar in `docs/dev/home.md`), the greeting (`greeting.ts`: the card under it and the line above it, templates picked without repeats), the day's one order (`dayOrder.ts`: fixed-time items and the planned steps laid out against the clock; Start here and Today's list read it, `dayOrderOf` in `src/app/model.ts`), memory notes and their format in a prompt (`memory.ts`), memory import and export as Markdown (`memoryMd.ts`), and the one name-matching rule (`names.ts`: `findByName`, `mentions`); areas in use (`areas.ts`: select order, grouping, half days; the rules of areas themselves are `places.ts`), and what the lists look at (`view.ts`: the saved view, kept on the device under `reussite.placeview`, resolved against `here` with the fall-back to the region) and a person's page (`people.ts`); phase 4b's: a step's short name for calendars (`label.ts`) and areas of a place (in `places.ts`: `zoneOfPlace`, `onPage`, `placeAndAreas`, `parentProblem`); and phase 4's: Maps links (`mapsLink.ts`), the offers for addresses and people (`offers.ts`, and `offerPick.ts`: what a picked offer sets on the step), the Google Takeout parser (`takeout.ts`) and the trip pack's text (`trip.ts`); and phase 4b's: short names (`label.ts`), areas (`places.ts`), what the calendar exports say of a step (`calItems.ts`: the all-day events and the three levels of detail; `ics.ts` only formats), the feed's text (`feedText.ts`, shared with the connector) and what the Calendar tab shows on each day (`calView.ts`: the hour grid's events and the all-day row); and the morning's proposal (`propose.ts`: `proposeDay`, the candidates in five sections the AI words and ranks); and the Dove clock's fractions, pie, ticks and the time as a phrase for its label (`clockFace.ts`). Every rule here has a unit test.
- `src/data/` — the data model (`schema.ts`), hybrid logical clock (`hlc.ts`), documents with per-field clocks and tombstones (`doc.ts`), Dexie database (`db.ts`), migrations, v1 importer, backups, settings defaults.
- `src/app/` — state (`store.ts`: signals mirroring IndexedDB, and the only place that writes), read helpers (`model.ts`), write actions (`actions.ts`), shared UI and sheets, `More`/`Fold` (the folded optional fields of every form and the folded Settings sections, `More.tsx`), theme; Home's logic, exchanges and Undo (`home.ts`), the views and the hash (`nav.ts`), keyboard detection for the bottom bar (`keyboard.ts`), Memory's writes (`memoryActions.ts`), addresses and people (create, edit, record a visit, last seen: `actions.ts`; offers and categories: `model.ts`), the read-only banner's Reload (`reload.ts`), the "N done" fold under a list (`DoneFold.tsx`, with `splitDone` in `lists.ts`), the greeting lines already shown today (`greetingShown.ts`), the area the lists are narrowed to (`areas.ts`, from the place menu's View) and the areas' tag and editor (`AreaUi.tsx`), the place menu (the pill's two ticks, I'm here and View, and the Places sheet that adds places and areas: `PlacesSheet.tsx`), Addresses and people's sheets and the after-visit screen (`AddressSheets.tsx`) and the Takeout import (`TakeoutSheet.tsx`). Home's clock, colour fills and no hands, small beside the wordmark: an hour pie inside twelve ticks, a minutes ring, a thin seconds ring that moves each second only while the page is visible and not with reduced motion (`DoveClock.tsx`, an SVG in the `--clk-*` colours of `tokens.css`, the fractions, pie and ticks in `src/domain/clockFace.ts`); Home never scrolls (`.app[data-view="home"]` is one screen tall, the mark and greeting shrink first, `.homecards` scrolls inside, `html.home-lock`; `tests/e2e/homefit.spec.ts`); only Home names the app, the other tabs' masthead (`Mast` in `App.tsx`) is the date and the place pill (on Today the minutes timed so far sit between them, `.mast-timed`: it takes only the room left and drops out whole when there is none) with a visually hidden `h1` and the iPhone home-screen app's top (`ios.ts`: the `ios-app` class on `<html>` that raises `--sat`, the top padding of every screen, to at least 62px, and a fixed band of that height in the page's ground, `html::before` in `tokens.css`, covers the strip under the status bar so that scrolled content is never seen under it; `tests/e2e/topband.spec.ts`).
- `src/ai/` — AI (phase 2): provider adapters (`adapters.ts`), the one entry point `ask`/`askChanges` with "Show me what's sent" (`ask.ts`), prompt and context building (`context.ts`), the change-set contract (`changeset.ts`, documented in `docs/CHANGESET.md`), pure plan-and-apply (`apply.ts`) with the app's writer (`writer.ts`), the review screen (`Review.tsx`), the command box, Ask any AI and Paste the reply (`ui.tsx`), Settings → AI (`AiSettings.tsx`), the pure Undo shared with the relay (`undo.ts`), model prices and the monthly cap (`prices.ts`), and first-run set-up with an AI (`setup.ts`: its prompt, the pack for any chatbot and the reading of its reply; the ops are `settings.update` and `place.create`; `settings.update` is the app's only, the connector refuses it). ## Invariants

One list. The first eight are about the product, the rest about how sessions work.

1. **Never lose data.** No hard deletes: set `_del`. Never drop a field you don't recognise. Importing and restoring merge; they don't replace.
2. **Migrations are mandatory.** Any change to stored shapes bumps `SCHEMA_VERSION` and adds a function to `src/data/migrations/index.ts`, with a test on fixtures of every earlier version. Migrations run before any write, after a local backup.
3. **Settings are data.** New settings get defaults in `DEFAULT_SETTINGS`; an update never resets a value the person chose.
4. **Every write goes through `store.ts`** (`createDoc`, `update`, `upsert`, `removeDoc`) so it gets field clocks and respects read-only mode.
5. **No hard-coded UI text, and nothing personal.** Every string goes in `en.ts` and `fr.ts` in the same change. French typography is applied automatically.
6. **`private/` is never committed, printed or sent anywhere.** Checks that read it print counts only.
7. **Tests must pass before a commit:** typecheck, the unit tests, and the e2e specs of what you touched; the whole `npm run e2e` before a merge or a deploy. Nothing may scroll sideways at 320, 375 or 430 px.
8. Links open outside the app; only schemes in `ALLOWED_SCHEMES` are accepted.
9. **A request is done, or the last message says why not.** Done means a passing test or a commit hash that names it. Never close one as "check on the phone" or "not now". A backlog only on the owner's word. The final message lists every request of the session as done (hash, how verified) or not done (reason).
10. **Verified means a test.** A passing test that exercises the behaviour at 320×568 and 390×844, in English and French. Typecheck alone is not verification. If only an iPhone can show it, it goes on a phone checklist and stays unverified until the owner ticks it.
11. **Phone-only behaviour is unverified.** iOS top and notch, push and 320 px wraps can't be proven by emulation. Add a test that measures the symptom at 320, 375 and 430, and write "unverified on device" in the last message.
12. **The owner's words outrank the plan.** If a plan or prompt says "only if it blocks" about something the owner asked for, do it anyway and say so. Requests given in a session are done in that session; never file them for the owner to apply, and never write "proposed brief edits" in place of the work.
13. **Look before reversing.** Before changing a surface, grep `DECISIONS.md` for it. If the request reverses an entry, name that entry, ask once, then mark the old entry superseded.
14. **A repeated request means the last fix failed.** Find the earlier commit and add the test it lacked.
15. **One implementation per interaction.** Grep before adding a button or a rule (Drop, Start here, calendar text). Extend the existing one, and merge duplicates you touch.
16. **If an item turns out much bigger than described,** stop that item, report why, and go on to the next.
17. **If a prompt looks cut off, say so before starting.**
18. **Leave nothing running.** Kill every background job and watcher you start before you finish.
19. **When your own change breaks a test, fix the change and carry on.** Never fix it by weakening a test or changing what it asserts.
20. **When wording doesn't fit, use the shortest neutral label that does,** and say so in the report.
21. **Never deploy with a failing check:** stop and report instead.
22. **Otherwise, stop and ask only when a fix would change something the owner decided.**
